# Intelligent Face Tracker with Auto-Registration and Visitor Counting

This project is a Python-based prototype for detecting and tracking faces in video, matching face embeddings against registered visitors, and recording visitor entry/exit events.

## Features

- Face detection using a YOLO face model.
- Face embeddings using InsightFace/ArcFace.
- Object tracking using Ultralytics tracking with ByteTrack.
- SQLite storage for registered visitor records and event history.
- Automatic registration when a detected face does not match a saved embedding above the configured similarity threshold.
- Timestamped face-crop storage for entry and exit events.
- Application event logging in `logs/events.log`.
- Configuration through `config.json`.

## Requirements

- Python 3.11
- PyTorch
- Ultralytics
- OpenCV
- InsightFace
- ONNX Runtime
- NumPy

The application uses a local YOLO model and InsightFace's `buffalo_l` model. InsightFace may need to download its model files the first time it runs.

## Setup on Windows PowerShell

Open PowerShell in the project directory.

Create and activate a virtual environment if one does not already exist:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the project dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Install a compatible PyTorch build if it is not already installed. For CPU-only systems, use the official PyTorch installation instructions: https://pytorch.org/get-started/locally/

Check the Python scripts for syntax errors:

```powershell
python -m py_compile main.py visitor_events.py visitor_system.py
```

## Configuration

Review `config.json` before running the application. The `frame_skip` setting controls how many frames are skipped between configured processing cycles. Confirm its exact interpretation in the implementation before changing it.

## Run the visitor event application

Activate the virtual environment and run:

```powershell
python visitor_events.py
```

Use `Ctrl+C` or close the display window to stop the application, depending on the running loop and its exit handling.

The `main.py` and `visitor_system.py` scripts are also present as separate detection and visitor-system implementations. `visitor_events.py` is the current entry/exit event workflow.

## Data and outputs

- `visitors.db`: registered visitor records and event history.
- `logs/events.log`: diagnostic and application events.
- `logs/registered_faces/`: saved images for registered faces.
- `logs/entries/YYYY-MM-DD/`: entry-event face crops.
- `logs/exits/YYYY-MM-DD/`: exit-event face crops.

Do not delete the database or logs if you need to preserve previous test results. Repeated test runs can append additional events and registration records.

## Visitor counting and limitations

A database registration count is not necessarily the same as the number of distinct real-world people. Recognition quality depends on face-image quality, lighting, pose, and the similarity threshold.

Tracker IDs identify tracks within a tracking session and should not be treated as permanent visitor identities. Entry and exit events depend on crossing the configured virtual line in the expected direction.

Validate both crossing directions with suitable test footage. If a video contains no qualifying exit crossing, the application may correctly produce no exit event for that video.

This is a prototype and should be evaluated for false matches, missed detections, repeated events, and performance before real-world deployment. Face images and embeddings are sensitive biometric data and should be handled with appropriate consent, access controls, and retention practices.
